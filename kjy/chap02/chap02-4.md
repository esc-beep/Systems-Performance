# CHAP 02-4 관점 

성능 분석에는 워크로드 분석, 자원 분석의 두가지 관점이 존재함. 소프트웨어 스택을 top-down으로 분서가헉나 bottom-up으로 분석 가능 

## 2.4.1 자원 분석 
* 자원 분석은 시스템 자원을 먼저 살펴보는 데서 시작 (CPU, 메모리, 디스크, 네트워크 인터페이스, 버스, 인터커넥트 등)
* 성능 문제 조사, 수용량 계획을 진행함
    * 성능 문제 조사: 특정 자원이 성능 문제를 일으키고 있는지? 
    * 수용량 계획: 새로운 시스템 설계 시 자원의 크기를 결정하거나 기존 시스템 자원이 언제 고갈될지 예측하는데 도움을 줌 
* 자원 분석에 적합한 지표: IOPS, throughput, utilization, saturation 
    * 특정 자원이 처리하도록 요청 받은 작업이 무엇인지, 주어진 부하에 대해 해당 자원이 얼마나 사용되었거나 포화되었는지를 측정함. 
    * 지연시간 지표도 주어진 부하에 얼마나 잘 대응하고 있는지 측정하는데 유용할 수 있음 

## 2.4.2 워크로드 분석 
워크로드 분석은 애플리케이션에 가해진 부하, 그에 대한 애플리케이션의 응답 -> 애플리케이션의 성능을 검사함 
* 워크로드 분석 목표: 
    * 요청: 애플리케이션에 가해진 부하 
    * 지연시간: 애플리케이션의 응답 시간
    * 완료: 오류 발생 여부 확인

* 워크로드 특성화(workload characterization): 각 부하의 속성을 확인하고 요약하는 과정 
* 지연시간(응답시간): 애플리케이션의 성능을 나타내는 가장 중요한 지표 
* 워크로드 분석에는 문제를 발견/확인하는 작업이 포함됨 
    * 분석의 시작 지점은 애플리케이션!
* 워크로드 분석에 적합한 지표: 
    * throughput(초당 트랜잭션 수)
    * 지연시간
